# 定制模块与剩余接入点

2026-10-27：基于小主机原始快照完成本地模块化。生产主机未操作；实际配置、人格卡、会话状态和原始归档保持不变。

## 已分离的部分

| 能力 | 独立维护位置 | 与上游的连接方式 |
| --- | --- | --- |
| 峰谷与节假日判定 | `custom/policy/autonomy-schedule.js` | `src/` 保留兼容转发入口 |
| 高峰/闲时权限矩阵 | `custom/policy/group-policy.js` | 配置加载、消息与发送关卡调用 |
| 每日定时总开关 | `custom/policy/group-master-schedule.js` | 复用原进程的检查循环 |
| 参数校验 | `custom/policy/console-controls.js` | 原控制接口调用 |
| 群聊旁观、选择性续聊、冷却、分条预算 | `custom/runtime/group-chat.js` | 显式注入上游状态及服务函数 |
| 控制台设置保存 | `custom/runtime/control-settings.js` | 原 HTTP 路由转交处理 |
| 局域网代理入口校验 | `custom/runtime/console-gateway.js` | 原鉴权关卡调用 |
| DSH 安装预设同步 | `custom/runtime/preset-sync.js` | 保留原函数签名的短接入函数 |
| 控制台开关页、导航、状态与交互 | `custom/console/` | 上游 HTML 原样保留，返回前组合片段 |
| 已安装的 DSH 插件副本 | `integrations/dsh/` | 独立安装材料，不自动部署 |

这次没有修改开关含义、触发概率、等待时长、峰谷规则、提示词内容或配置字段。每个桥接实例创建自己的定制运行时；测试覆盖实例间隔离。

## 仍需接入或单独处理的部分

| 部分 | 为什么没有完全独立 | 当前交付方式 | 上游更新后如何处理 |
| --- | --- | --- | --- |
| `src/bridge.js` 的事件入口、唤醒调度与优先级 | 上游没有覆盖这些环节的插件钩子；只在外部模块判断会被其他入口绕过 | `custom/upgrade/core.patch` 中的接入修改 | 试打补丁；相关函数改名或结构变化时人工适配 |
| MCP 读/等待/标记已读的衔接 | 观察窗口必须和上游消息水位、令牌及等待连接保持一致 | 同一核心接入补丁，实际等待逻辑已移到模块 | 检查接口契约及续聊回归 |
| 发送前复查、取消在途任务、会话退役 | 需要在真实发送、排队和完成事件处调用；不能仅靠提示词 | 同一核心接入补丁 | 检查所有发送出口和模式切换路径 |
| 仿真 YAML 中的工具协议及行为规则 | DSH 预设是完整 YAML 插件行，当前读取/编辑流程没有通用的外部提示词引用机制 | 保留现有 YAML，作为单独文件的补丁差异 | 冲突时比较新旧规则，保留安全不变量，不盲目覆盖 |
| 模板与控制台同步后的已部署预设 | 两者采集时已经不同，代表不同用途 | `plugins/`、`dsh/` 与 `integrations/dsh/` 分开保留 | 由管理员决定恢复哪份，补丁工具不操作外部 DSH 安装 |
| DSH 的异常 JSON 有界重试 | 属于 DSH provider 配置，无法作为 qq-bridge 内部插件替代 | 保留 `patches/deepseek-json-retry.patch.yml` 与私有部署快照 | 单独核对新 DSH 的配置结构后使用，不自动覆盖账户配置 |
| HTTPS、证书、网段、防火墙、systemd | 属于主机部署层，含路径、账户和私有凭据 | `.private/deployment/` 保存实际配置 | 源码补丁不部署这些内容；迁移时另行恢复和验证 |
| 部分历史诊断、迁移脚本 | 针对旧阶段或特定 DSH 安装路径 | 保留历史源码及说明，不作为默认升级步骤 | 不直接重复执行；确认目标环境后使用 |
| 原测试夹具与预览入口 | 需要注入真实独立模块及组合后的网页才能继续测原契约 | 补丁中的测试接入修改 | 随上游测试框架适配，不能将缺失注入当作行为通过 |

目前仍没有新增跨时段待回复队列、群内个人黑名单或完整长期记忆管理系统；此次重构没有扩充这些功能。

## 控制规则保持原样

1. 白名单和权限先限定对象。
2. 总开关关闭时，所有群聊均不回复，包括主人艾特；主人私聊保留。
3. 定时启用时按北京时间开关，手动操作会停用定时。
4. 开启后按高峰/闲时策略矩阵处理。
5. 普通群友及群内话题保持选择性参与；允许唤醒不等于每句必回。
6. 续聊窗口、冷却、分条与限流继续生效。

## 维护原则

`custom/` 是独立定制的维护入口；`src/bridge.js` 中保留必要接入点。不得为了减少补丁行数，删除出站复查、权限变化取消或令牌隔离。

`patches/` 是历史参考，不能按文件名逐个重新叠加。今后的统一应用入口是 `custom/upgrade/`。升级流程、检查命令和失败处理见 [UPSTREAM_UPGRADE.md](UPSTREAM_UPGRADE.md)。
