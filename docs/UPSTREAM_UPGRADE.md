# 跟进上游与应用定制补丁

## 交付内容

`custom/upgrade/` 是可以单独复制走的本地补丁包，包含：

- `apply.mjs`：检查与应用工具，只使用 Node.js 内置模块和本机 Git。
- `core.patch`：相对固定上游基线的统一接入补丁，可直接阅读。
- `manifest.json`：基线来源、目标文件及文件校验值。
- `files/`：独立模块、兼容入口、插件副本、测试及说明文档。
- 原始 `LICENSE` 与本地 `NOTICE`。

当前基线是 qq-bridge `0.2.1-r1`，上游提交 `a49877f4e58d04e47532d44b803360d0f001160d`。该提交用于定位补丁来源，不能保证未来所有版本都具有相同接口。

## 在上游新版本副本上操作

需要 Node.js 22.13 或更高版本以及 Git。先准备一个独立的上游源码目录；不要直接覆盖正在运行的部署。

在本项目目录中先检查：

```sh
node custom/upgrade/apply.mjs check --target <上游源码目录>
```

检查会在临时目录试打核心补丁、校验定制模块、检查 JavaScript 语法和控制台锚点；不会改目标源码，不启动 QQ/DSH，也不会调用模型或安装依赖。

检查通过后应用：

```sh
node custom/upgrade/apply.mjs apply --target <上游源码目录>
```

工具先重复预检，再备份将要改动的文件，最后写入补丁及独立模块。原文件保存在目标目录的 `.qqbridge-custom-backups/`，并有恢复清单。普通写入异常时会尝试恢复已经写过的文件；若进程被系统终止，应根据备份清单恢复或重新准备干净副本。

同一补丁重复运行会识别已应用状态；已应用文件若又有本地修改，会停止，避免覆盖。不同版本的定制包应在干净的上游副本上处理，不直接叠加。

随后准备该上游版本需要的依赖，并运行：

```sh
node scripts/test-custom-regression.mjs
```

本次已在本地干净的固定基线副本上实际应用补丁并回归。对未来新版本，成功打补丁仍需通过回归与人工查看差异；上游接口语义改变不一定表现为文本冲突。**不能承诺任何未来版本都只需一次打补丁。**

## 不会覆盖的内容

应用工具明确禁止目标为以下路径：

- 实际 `config.json`、`.env*`、`.npmrc`、账户凭据。
- `roles/`、`state/`、`audio/`、`node_modules/`、`.private/`。
- Git 数据目录及既有升级备份。

根目录 README 和 config.example.json 也不作为升级覆盖文件。新上游的说明与示例可以保留；本定制的说明在 `custom/README.md` 与 `docs/` 中。配置字段与含义保持兼容，原实际配置可继续保留。

符号链接、越界路径、已有但内容不同的独立模块会被拒绝。补丁不连接小主机，不部署反向代理/防火墙/证书，不修改 AstrBot，不操作远程仓库。

## 如果报告冲突

- 核心补丁冲突：根据报出的文件检查新的事件、等待、发送或测试接口，再调整接入补丁。
- 控制台锚点冲突：修改 `custom/console/patches.json` 中的锚点及对应片段，保持 DOM ID 和交互契约。
- 独立模块同名冲突：先比较上游新增实现与本地模块，不能直接强制覆盖。
- 预设 YAML 冲突：比较安全规则、工具协议与自己的修改，手动合并；不要删除安全不变量换取通过。

冲突预检失败时，目标文件不改变。工具不使用强制覆盖或自动丢弃上游变化。

## 修改定制后重新生成补丁包

维护者应先修改 `custom/policy/`、`custom/runtime/`、`custom/console/` 等源文件及必要的接入点。保留一个未修改的上游参考目录，然后：

```sh
node scripts/build-custom-upgrade.mjs --upstream <未修改的基线源码目录>
node custom/upgrade/apply.mjs check --target <未修改的基线源码目录>
node scripts/test-custom-upgrade.mjs --upstream <未修改的基线源码目录>
```

本次参考目录位于本地忽略的 `.private/upstream-a49877f4/`。构建器只读取 Git 的已跟踪/未忽略源码清单，不提交、不推送；真实配置、人格、状态和依赖不会打进补丁包。不要只改生成包里的副本，否则下一次构建会被维护源文件替换。

改用新的基线时，需要完成合并、更新来源记录和清单，再重新构建、验证；这不是工具自动帮你适配任意上游版本的功能。
